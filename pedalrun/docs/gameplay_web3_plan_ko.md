# Pedalrun Gameplay and Web3 Plan

## 목적

Pedalrun은 Web3 이더리움 결제 시스템과 온체인/오프체인 보상 흐름을 빠르게 테스트하기 위한 배포 중심 자전거 배달 러너 게임이다.

게임 자체는 복잡한 오픈월드가 아니라, 반복 개발과 배포가 쉬운 러너 구조를 우선한다. 플레이어는 자전거를 타고 직선 도로를 달리며, 일부 구간에서 좌회전/우회전 선택지가 나타나는 방식으로 스테이지를 진행한다.

## 핵심 게임 루프

1. 배달 주문을 받는다.
2. 제한 시간 안에 목적지까지 주행한다.
3. 거리, 시간 단축, 아이템, 연속 성공에 따라 점수를 얻는다.
4. 신호 위반, 배달 지연, 충돌 등으로 평판 별점이 감소한다.
5. 별점이 모두 소진되면 실패한다.
6. 최종 점수는 랭킹 시스템에 등록된다.
7. Web3 테스트 단계에서는 결제, 패션 아이템, 부스터, 랭킹 보상 등을 Ethereum/Solidity와 연결한다.

## 스테이지 구조

### 기본 형태

스테이지는 일자 도로 기반으로 시작한다.

```text
[ | ]----[ | ]----[ | ]
       ┼        ┼
```

- `[ | ]`: 주행 가능한 도로 구간
- `┼`: 좌회전/우회전 또는 교차로 이벤트 구간
- 도로는 여러 조각을 이어 붙이는 무한 러너 방식으로 생성
- 초반에는 3차선 또는 좁은 자유 조향 도로로 시작
- 이후 교차로에서 좌회전/우회전 분기 가능

### 스테이지 구성 요소

- 직선 도로
- 교차로
- 좌회전 구간
- 우회전 구간
- 신호등 구간
- 장애물 구간
- 아이템 구간
- 배달 목적지 구간

## 점수 시스템

점수는 일반 스코어와 보너스 스코어로 나눈다.

```text
Final Score = Normal Score + Bonus Score
```

### 일반 스코어

일반 스코어는 안정적인 기본 점수다.

- 주행 거리
- 배달 성공
- 제한 시간 대비 빠른 도착
- 충돌 없이 주행한 거리

예시:

```text
Distance Score = 주행 거리 * 거리 계수
Time Save Score = 남은 시간 * 시간 보너스 계수
Delivery Score = 배달 성공 기본 점수
```

### 보너스 스코어

보너스 스코어는 플레이 실력과 연속 성공 보상이다.

- 도로 위 아이템 획득
- 지속 퀘스트 성공
- 연속 배달 성공
- `x2` 점수 부스터
- 완벽 배달
- 신호 준수 보너스

예시:

```text
Combo Bonus = 연속 배달 횟수 * 콤보 계수
Booster Bonus = 일정 시간 동안 획득 점수 * 2
Item Bonus = 아이템별 점수 합산
```

## 평판 시스템

평판은 별 5개로 표현한다.

```text
★★★★★ = 최고 평판
☆☆☆☆☆ = 실패
```

평판은 점수이면서 목숨 역할도 한다.

### 평판 감소 조건

- 배달 시간이 미흡함: `-0.5`
- 신호 위반: `-0.5`
- 장애물 충돌: `-0.5` 또는 `-1.0`
- 경쟁사 라이더와 충돌: `-0.5`
- 배달로봇 `백초`와 충돌: `-0.5`
- 진입불가 바리게이트 충돌: `-1.0`

### 평판 보상 조건

- 연속 배달 성공
- 신호 준수 연속 성공
- 완벽 배달
- 일정 거리 무사고 주행

단, 평판 회복은 남발하지 않는 것이 좋다. 별점이 목숨 역할을 하므로 회복 수단은 희소해야 한다.

## 장애물

### 노란 진입불가 바리게이트

- 고정 장애물
- 충돌 시 큰 페널티
- 차선 변경 또는 조향으로 회피
- 초반 스테이지에서 가장 명확한 장애물로 사용

### 배달로봇 `백초`

- 움직이는 장애물
- 천천히 좌우 또는 전방으로 이동
- 충돌 시 평판 감소
- 패턴이 읽히도록 이동 속도는 플레이어보다 느리게 시작

### 경쟁사 라이더

- 움직이는 라이벌 오브젝트
- 플레이어 진로를 방해하거나 같은 차선을 달림
- 충돌 시 평판 감소 및 속도 감소
- 후반에는 경쟁사 라이더를 추월하면 보너스 점수 지급 가능

## 랭킹 시스템

최종 점수는 랭킹 시스템에 들어간다.

랭킹 기준:

- 최종 스코어
- 일반 스코어
- 보너스 스코어
- 평판 별점
- 배달 성공 수
- 총 주행 거리
- 플레이 시간

초기 구현은 오프체인 로컬/서버 랭킹으로 시작하고, Web3 테스트 단계에서 온체인 기록 또는 지갑 서명 검증으로 확장한다.

## Web3 / Solidity 연동 계획

Web3는 게임이 먼저 구동된 뒤 붙인다. 게임 루프가 없는 상태에서 결제 시스템을 먼저 붙이면 테스트 기준이 흐려진다.

### 테스트 대상

- Ethereum 지갑 연결
- 결제 트랜잭션
- 자전거 패션 아이템 구매
- 배달 박스 스킨 구매
- 부스터 구매
- 랭킹 보상 지급
- NFT 또는 SBT형 라이더 배지

### Solidity 후보 컨트랙트

- `BikeFashionStore`
  - 자전거/라이더 패션 아이템 구매
  - 아이템 소유권 확인

- `DeliveryPass`
  - 시즌 패스 또는 테스트 패스
  - 특정 스테이지 접근 권한 관리

- `ScoreRegistry`
  - 최종 점수 기록
  - 지갑 주소별 최고 점수 저장

- `RewardVault`
  - 테스트 보상 지급
  - 랭킹 보상 또는 이벤트 보상 관리

## MVP 기준

첫 번째 플레이 가능한 버전은 아래 조건을 만족하면 된다.

- 자전거가 `W/S` 연타로 전진
- 마우스/터치 드래그로 조향
- 직선 도로가 이어짐
- 최소 1종 장애물 존재
- 거리 점수 표시
- 제한 시간 표시
- 별 5개 평판 표시
- 충돌 또는 지연 시 별점 감소
- 최종 점수 결과 화면 표시

이 MVP가 완성된 뒤 Web3 결제 테스트를 붙이는 것이 가장 안전하다.
